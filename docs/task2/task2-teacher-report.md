# 科研实训任务2完成情况汇报

## 一、任务目标

本阶段围绕用户多模态数据管理与个人画像生成展开。任务目标是对手机智能体在真实应用场景中采集到的多模态数据进行结构化管理，从原始运行记录、视觉摘要、应用日志中抽取可用信息，进一步构建信息之间的因果关系、时域关系、空域关系，形成可检索、可解释、可追溯的用户画像和待办事项。

本阶段特别强调数据闭环能力。系统需要从任务1产生的微信、小红书、美团、淘宝等应用运行数据出发，完成数据抽取、关系建模、画像生成、待办生成、外部记忆写入、RAG 检索验证等环节，形成面向后续主动服务能力的用户记忆基础。

## 二、数据来源与处理范围

本阶段使用任务1已经成功运行的手机智能体记录作为输入数据，覆盖社交沟通、内容浏览、生活服务、购物浏览等典型移动端场景。

处理的数据包括：

- 微信聊天场景的视觉摘要与上下文信息
- 小红书浏览记录页面状态
- 美团订单页面中的服务类型、订单状态、消费信号
- 淘宝足迹页面中的商品类别、店铺或品牌信号、价格信号
- 每次运行产生的 run_summary、daily-log、截图路径和结构化 VLM 输出

数据处理过程中只保留摘要级信息和结构化实体，不扩散原始聊天文本。该设计体现了隐私保护意识，也保证了画像生成结果具有证据来源。

## 三、技术路线

本阶段实现了一条从多模态数据到外部记忆检索的完整技术路线。

第一步是数据采集整理。系统读取任务1的成功运行目录，自动收集 run_summary、daily-log、截图路径和应用元信息，形成统一的运行清单。

第二步是信息抽取。系统针对不同应用场景设计抽取规则，将微信摘要映射为社交上下文事件，将小红书页面状态映射为内容历史状态事件，将美团订单映射为生活服务消费事件，将淘宝足迹映射为购物浏览事件。

第三步是关系建模。系统基于事件时间、应用来源、实体内容和业务含义，构建 before、after、same_day、behavior_causal、spatial 等关系。该部分使画像具备事件证据、关系说明和可追溯来源。

第四步是画像和待办生成。系统根据事件和关系生成用户画像条目，并对弱证据场景生成候选待办。画像输出包含类别、结论、证据事件、置信度、时间范围、服务可用性等字段。

第五步是外部记忆写入与 RAG 检索。系统将事件、关系、画像、待办统一转化为 Mem0 记忆记录，写入外部 Milvus 向量库，并通过 Mem0 搜索接口进行召回。该设计使任务2结果具备外部记忆管理能力，也为后续任务中的主动推荐、长期记忆更新、个人助理服务提供基础。

## 四、系统实现

本阶段新增了 profile_pipeline 模块，主要包含以下功能：

- ingest.py 负责收集成功运行记录和原始证据路径
- extract.py 负责从多模态结构化输出中抽取用户事件
- relation.py 负责构建时域、空域和因果关系
- profile.py 负责生成用户画像和候选待办
- search.py 负责提供轻量本地检索能力
- mem0_rag.py 负责连接 Mem0 与 Milvus，并完成外部 RAG 写入和检索
- cli.py 负责提供命令行入口，支持构建画像、构建 RAG、检索、生成报告
- test_profile_pipeline.py 负责覆盖核心处理流程和外部 RAG 接口行为

本阶段保持 profile-mem/manage_profile_memory.py 原有实现，通过依赖版本降级与配置适配复用已有 Mem0 管理脚本。该处理方式保持了原有工具链的稳定性，也降低了对已有模块的侵入。

## 八、科研能力体现

本阶段训练了从工程任务到科研问题的完整思维过程。

在问题建模方面，我将多模态观察结果转化为事件、实体、关系、画像、待办等不同层次的数据结构。这种分层建模方式增强了系统的可解释性和可维护性。

在证据管理方面，每条画像和待办都保留 source_event_ids，用于追踪其来源事件。该设计保证了系统输出可以回溯到原始运行记录，也方便后续进行错误分析和人工审核。

在关系建模方面，系统同时考虑时域关系、空域关系和行为因果关系。该设计使任务2不仅完成信息抽取，也初步具备用户行为理解能力。

在系统集成方面，我完成了本地任务管线与外部 Mem0/Milvus 服务的连接。系统可以将结构化画像写入外部向量记忆库，并通过 RAG 查询返回相关记忆。该能力为后续个性化服务、主动提醒、长期记忆更新提供了基础。

在实验验证方面，我使用单元测试验证核心逻辑，并使用真实 Mem0/Milvus 服务验证外部写入和召回。测试覆盖功能正确性、证据绑定、外部接口调用和报告生成，体现了科研实训中对可复现性和工程可靠性的要求。

在隐私保护方面，系统只保留摘要级社交上下文，不保存原始聊天文本。画像生成结果均标注置信度和服务可用性，避免将弱证据误用为稳定长期偏好。

任务2已经完成从多模态数据管理到外部 RAG 记忆检索的完整闭环。系统能够读取任务1产生的手机智能体运行数据，抽取用户事件，构建时域、空域和因果关系，生成个人画像和候选待办，并将结果写入 Mem0 + Milvus 外部记忆服务进行检索验证。
